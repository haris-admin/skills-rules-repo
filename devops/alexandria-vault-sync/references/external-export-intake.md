# External AI profile / knowledge-export intake

Use when a profile or knowledge export generated by ANOTHER AI system (Perplexity memory export, ChatGPT profile dump, etc.) arrives for vault ingestion — including exports that claim to be "alexandria-compatible" or that tried to fetch the private alexandria repo themselves.

## Procedure

1. **Preserve the raw export verbatim** under `vault/inputs/<source>-<topic>-<yyyy-mm-dd>_<hhmm>.<ext>` — the faithful, recoverable source (same rule as raw library/ mirrors).
2. **Cross-check every claim against authoritative stores BEFORE adoption**: memory, `~/.hermes/ops/environment.md`, refined keep-files, chambers, and a live repo listing via the OPERATOR PAT when the export names repos.
3. **Classify into a rationalization table** (this is the value-add, not the file copy):
   - `✅ NEW + ALIGNED` — adopt, each into its proper home (environment.md tool/goal lines by name only; keep-file framing notes; chambers)
   - `🔁 ALREADY KNOWN` — no action
   - `⚠️ CONFLICTING / STALE` — do NOT adopt; flag with the specific conflict
   - `🗑️ NOISE / DROP` — metadata, audit trails, capability notes, garbage queries
4. **Write the rationalization doc** under `vault/refined/<topic>-rationalization-<yyyy-mm-dd>.md` with provenance header + open questions; raw export and rationalization are separate files.
5. **Commit raw + rationalized + adopted deltas** with scoped `git add` (never `-A`), secret scan first.

## Pitfalls

- **An external export's claims about the OWNER do not override the vault's authoritative owner framing.** An export that describes the owner as "employee elsewhere" and their flagship product as "not founder / founder is someone else" contradicts vault + fleet evidence (owner runs the product, its repos, and the agent estate). Label it `STALE/MISREAD`, do not propagate, leave one open confirmation question for the owner rather than silently rewriting identity facts.
- **Pricing/subscription deltas between an export and memory are UNRESOLVED, not updates.** When the export names a different plan/price than memory holds, ask the owner which is current — do not overwrite memory with the export's number.
- **Export metadata is noise.** The exporting system's own capabilities/limitations, audit trail, file-format history, and data-inclusion boilerplate carry no durable knowledge — drop them from the rationalized doc.
- **An export that failed to fetch the private repo is evidence the external AI was pointed at our vault.** Its "compatibility" claims are aspiration, not verified alignment — treat the export as a draft to audit, exactly like an AI-authored strategy doc.
- **Tool/subscription facts go in by NAME only** — never carry credential values from an export into environment.md or chambers.
