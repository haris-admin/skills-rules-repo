# Template: common rules for every implementer in a build wave

Copied from the HandleDispute spec 85 build (17 Nov 2026). Replace the spec and file names for another project. Put it in the scratchpad and tell each implementer to read it first; the per-wave prompt then names only the worktree, branch, base commit and tasks.


BINDING SPEC: openspec/changes/85-agent-research-reports/contract.md and report.schema.json in your worktree (accepted by the owner, D115; digest in contract.digest). Never edit them, proposal.md, tasks.md or anything under openspec/ (the coordinator ticks tasks). Read AGENTS.md sections 2, 3, 8, 8a, 12 first. Then read the contract sections for your tasks (section 4 requirements and test ids T85.Rnn.k, 6 routes, 7 data model, 8 status words, 9 settings, 10 to 14, 15 test plan). Already built and merged on dev (read, reuse, do not rebuild): settings (config.py), migration 037 and models (models/research_report.py), masking and logging (services/research_report_masking.py), report validation (research_report_validation.py), policy rules and routes, the S3 report store (research_report_store.py), attention items, recovery and the research email (research_attention_service.py, research_recovery_service.py, research_email_service.py, research_events.py). Hook point for callers: raise_item(...) then commit then notify_item_change(...).

TDD: for each task write the failing test first, run it, confirm it fails for the right reason (the missing behaviour, not an import error), then implement the minimum, then refactor. Cite the contract test id in each test name or docstring. A failing test means the implementation is wrong; never edit a test to make it pass. If the contract is ambiguous, contradicts itself, or cannot be met without a design decision, STOP that item, record it in your report and do not work around it.

AUDIT AND ROUTES: new routers register in backend/app/api/v1/api.py (one import, one include; main.py has none). Append to backend/app/core/audit_catalogue.py ONLY the activity codes your own routes or code write, in the same commit; never rename or reorder existing codes; regenerate docs/api/audit-catalogue-snapshot.json with `scripts/audit_catalogue_snapshot.py snapshot` and docs/product/audit-trail-label-review.md with `scripts/audit_catalogue_labels.py --output docs/product/audit-trail-label-review.md` (never hand edit). The existing guard requires every catalogue code to be written by real code, and every mutating route to write a catalogued activity (record_activity in the same transaction; record_activity_isolated for refusals) or have a written exemption in docs/api/audit-exemptions.json. The API contract of existing routes is frozen (the guard `scripts/api_contract_guard.py check` must show only additions).

OBSERVABILITY: each surface logs structured events with stable names per contract section 13 (no secrets, post-masking copy only, D87). No hardcoded tunable values: read settings at call time. Personal data follows D38/D72.

SAFE LOCAL RUN: before any test, server or alembic command run `source "How It Works/local-env.sh"` from your worktree root (forces local Postgres 5440, mock email, empty SMS). The worktree has no virtualenv: get the project environment path with `cd /Users/harishabib/code/github/haris-admin/ideas-handledispute/backend && poetry env info -p`; run its bin/python and bin/ruff with PYTHONPATH set to your worktree's backend directory and cwd = your worktree's backend directory; verify `python -c "import app; print(app.__file__)"` resolves inside your worktree. tests/conftest.py pins the shared database handledispute_security_test, which is already at migration 037. Other agents run tests at the same time on that one database: use unique fixture values, clean only the rows you create, never delete or truncate rows you did not create (stale rows from older runs exist, so a test must not assume an empty table), never drop or recreate that database. Never send a real email or call a real provider; the environment forces mock.

GATES before you report (from backend/): `ruff check . ../scripts`; `ruff format --check . ../scripts`; `python ../scripts/api_contract_guard.py check`; `python ../scripts/audit_catalogue_snapshot.py check`; your new test files plus tests/test_audit_*.py and tests/infra. Run pytest as `pytest ... > log 2>&1; echo exit=$?` and read the summary line AND the exit line before saying anything is green; never chain a commit after a pipe. A command that runs longer than two minutes is moved to the background: wait for it, do not start a second copy. Bandit under Python 3.13 is not installed: say it did not run. The full backend suite is the coordinator's job.

STYLE: no em dashes anywhere you write. Commit locally on your branch after each logical step (test:, feat:, fix:, chore:), pathspec commits, each message ending with: Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>

DENIAL OF AUTHORITY: do NOT git push, merge, rebase, reset or switch branches; touch no branch other than your own and no worktree other than yours. No deploy, workflow run, Terraform or AWS call, Plane call, real email, SMS or provider call, secret read or change, production access, or deletion of anything you did not create. Do not edit: openspec/**, AGENTS.md, CONTEXT.md, docs/engineering/*, infra/**, .github/**, migration 037, backend/app/core/config.py settings already built (add nothing without a contract setting), operations_exception_service.py. Other implementers work in parallel in other worktrees on the other tasks of this wave: do not build theirs. Existing services (identity_research_service.py, hermes_enrichment_service.py and their routes) may be edited ONLY where your task names the hook and only as the contract says, with the existing tests staying green.

REPORT: commits (hash and subject), `git diff --stat <base>..HEAD`, test counts with exit codes, gate results, anything not done and why, every interpretation or contract gap or conflict you hit (these go to the owner), assumptions you could not verify.
