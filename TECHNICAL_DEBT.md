# Technical Debt

A short register of known gaps in this repo — what's outstanding, what's been fixed, and when.

| Date | Item | Status | Notes |
| :--- | :--- | :--- | :--- |
| 2026-09-05 | README's Skills Catalog and Rules Catalog tables were hand-maintained and had drifted badly — the Skills table listed a small fraction of the ~290+ skills actually in the repo (most topic-category directories like `agent-governance-and-git/`, `compliance/`, `backend-and-database/` weren't represented at all), and the Rules table listed only 6 of 61+ files under `rules/`. | Resolved | Fixed by `scripts/generate_catalog.py`, which discovers every skill (`<top-level-dir>/<name>/SKILL.md`, mirroring `sync.sh`'s own discovery glob) and every rule (`rules/*.md`) directly from the filesystem and regenerates both tables. Run without flags to regenerate, `--check` to verify (used in CI). |
| 2026-09-05 | The README's CI badge linked to `.github/workflows/validate.yml`, which never existed in this repo — the badge had been broken/pointing at nothing since it was added. | Resolved | `.github/workflows/validate.yml` added: runs `scripts/validate.py` (structure/frontmatter) and `scripts/generate_catalog.py --check` (catalog freshness) on every push/PR to `main`. This also closes the catalog-staleness item above at the process level — a PR that adds/renames/removes a skill or rule without regenerating the README now fails CI instead of silently drifting again. |
| 2026-09-05 | The old hand-rolled table generator that produced the previous (now-replaced) README tables rendered raw YAML folding markers (`>-`, `>`) as literal skill descriptions for several skills (`api-design`, `api-endpoints`, `code-review`, `deploy-frontend`, `git-workflow`, `nginx-change`, `prompt-crafting`, `refactoring-clean-code`, `security-audit`, `test-driven-development`, `wizard-cycle`) instead of the actual folded text, and rendered every skill's link text as empty (`**[](...)**`). | Resolved | `scripts/generate_catalog.py` parses frontmatter correctly (folded `>-`/`>` scalars are joined, not left as literal markers) and always uses the skill/rule's real name as link text. |
| 2026-09-05 | `scripts/validate.py`'s own `parse_frontmatter()` has a latent bug: for a **plain, unquoted, multi-line** YAML scalar (no `>`/`\|` fold indicator) that continues onto an indented next line, it overwrites the assigned value with only the continuation line, silently discarding the first line's text. Confirmed live in `skills/accessibility/SKILL.md`'s `description:` field. `validate.py` doesn't currently catch this because it only checks description length/presence, not content correctness. | Open | Not fixed here — `scripts/validate.py` is out of scope for this change (only the catalog generator, README catalog sections, CI workflow, `CONTRIBUTING.md`, and this file were touched). `scripts/generate_catalog.py` carries its own corrected copy of `parse_frontmatter()` so the README catalog isn't affected, but `validate.py` itself should get the same fix in a follow-up so any future consumer of its parser doesn't inherit the bug. Only one file in the repo is currently affected by this pattern (`skills/accessibility/SKILL.md`), confirmed by scanning every `SKILL.md`'s frontmatter for the pattern. |
| 2026-09-05 | Four rule files have no summary text available between their `# ` H1 title and the next heading (`## Why this exists` follows immediately, with no introductory paragraph or blockquote): `rules/alembic-package-name-shadowing.md`, `rules/git-commit-hygiene-shared-worktree.md`, `rules/no-hardcoded-current-state-literals.md`, `rules/subagent-verification-protocol.md`. The generated Rules Catalog shows `-` in the Scope & Summary column for these. `scripts/validate.py` doesn't catch this either, since it only checks for an H1 title, not a following summary. | Open | Content fix, not a generator bug — each of these four rules would benefit from a one- or two-sentence summary paragraph (or `> ` blockquote) directly under its title, matching the convention most other rules already follow. Left as a content change for whoever owns each rule, since this pass is generator/CI/docs only. |
